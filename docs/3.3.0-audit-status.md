# 3.3.0 audit closure ledger

This ledger reconciles the **entire** [2026-09-05 implementation specification](audit-2026-09-05/IMPLEMENTATION_SPEC.md), including its proposals, risks, artwork, documentation, performance and release gates. It is a working release record, not a claim that every row has passed. The original audit remains historical evidence against its pinned commits.

Both builds are in scope: Forge 1.20.1 in `release/3.3.0`, and NeoForge 1.21.1 in the isolated `codex/3.3.0-neoforge-audit` worktree. Their Minecraft serialization and event adapters remain separate. Runtime claims below must be backed by fresh logs after the final edits; earlier 3.3.0 changelog prose is not sufficient evidence.

## Testing, release, and documentation (sections 9–11)

The automated core must cover all modes; pairwise sampling is appropriate only after economic, optionality and persistence invariants are covered deliberately. Exact tested artifact identities/hashes belong in the final validation record.

- Loader/JDK minimum/current matrix: pending; pinned first (Forge JDK17 / Neo JDK21).
- Optionality: fresh Ars-only, loaded base, each supported addon and full supported combination, dormant payload removal/reinstall, controlled unsupported version.
- Caster and spell lifecycle: survival/creative/adventure/spectator, login/logout/clone/death/dimension, fake and real players, integrated/dedicated server, instant/long/channel/recast/projectile/block/entity/self/multi-target/no-op/cancellation.
- Inventory and persistence: all source kinds, count1/64, output saturation, duplicate/native slots/proxy exhaustion, native metadata preservation, save/restart, old/future schemas and migration twice.
- Client/network: 50/150/300ms, duplicate/reordered packets and swaps, malformed bounded data, scales1–4, resource packs/reload, viewers, narrator/focus/localization/grayscale/reduced motion.
- Performance: record fixed hardware/JVM/world/baseline, p95/p99 server feature time, allocations/packets and churn. Proposed <1ms p95/<2ms p99 are targets, not achieved measurements.
- Release criteria 9.4.1–7 remain open until the P1 fixes, semantic loader parity, optionality, migration, server/UI quote agreement, artwork/accessibility and exact player/pack-author documentation each have evidence.
- Documentation deliverables 10.2: concise player guide and separate generated pack-author reference must include all mode units, carrier/ritual consumption, restrictions/addon evidence, source/well economics, caps, authority/reload, migration/removal, keybinds/accessibility, viewers and sanitized diagnostic output. Existing README/history is not sufficient alone.
- Preserve audit evidence and artifact provenance. Do not publish local development paths or dependency decompilation unintentionally; the source inventory and planning manifest remain reproducibility inputs.
