# Ars ’n’ Spells 3.3.0 audit closure ledger

This record closes the implementation work from [the 2026-09-05 audit](audit-2026-09-05/IMPLEMENTATION_SPEC.md) for both supported loaders. Forge 1.20.1 is the checkout at `release/3.3.0`; NeoForge 1.21.1 is the isolated checkout at `codex/3.3.0-neoforge-audit`. Loader adapters stay separate: Forge uses root NBT, Forge capabilities and Forge packets; NeoForge uses data components, attachments, `RegistryFriendlyByteBuf` and NeoForge payloads.

The ledger separates implementation, automated evidence and manual acceptance. A skipped optional scenario is reported as skipped; it is never counted as a passing gameplay assertion.

## Risks and incomplete guarantees

The following are explicit boundaries rather than hidden failures:

- Long channel/recast/nested casts beyond the bounded attempt lifetime, duplicate/reordered packets under 50/150/300 ms latency, two real clients, fake players and full disconnect churn still need a multiplayer session.
- The native Covenant ring handlers are pinned and neutralized/correlated by mixin, but the local Covenant/Blood Magic/Nature’s Aura profile did not fabricate ring inventories; live LP/aura debit, refund, conflict and toggle balances remain a gameplay gate.
- JEI proxy hiding is implemented for the supported Iron’s JEI surface. An EMI runtime and JEI/EMI transfer matrix were not available in the pinned review session and are not claimed as verified.
- Only the pinned dependency versions listed in the pack-author reference were executed. Declared minimum/latest version ranges require their own matrix before being advertised as certified.
- No fixed-hardware p95/p99 profiling run has been recorded. The audit’s `<1 ms p95` and `<2 ms p99` values remain targets, not measured results.
- Effect scaling is deliberately limited to adapters with an identified unit contract. Healing, shields, summons, duration, resistance and arbitrary “all effects” expansion are documented boundaries.
- Forge-to-Neo whole-world conversion is not implemented. The item migration paths are versioned and defensive, but they cannot decode arbitrary Minecraft/upstream world formats.
- Manual narrator, CJK/long-translation, grayscale/color-vision, reduced-motion and stock/resource-pack contrast certification remains a human acceptance step. The runtime harness proves labels, focusable controls, static state treatments, scales 1–4 and all three shipped packs.

The optional Phase 6 proposals (controlled multi-school resonance combinations and Source-fed ritual networks) remain intentionally unimplemented gameplay. They are marked as opt-in expansion in the audit and are not implied by ordinary resonance, Mana Wells or the 3.3.0 compatibility contract. This preserves bounded economics and avoids introducing an unverified third resource/network system.

## Architecture, migration and product work

- The shared Java 17 domain contracts, quote policy, school keys, mapping loader, inscription planner, payload budgets, request admission and deterministic fixtures are identical across the loader trees; `contract_parity.py` checks 32 files.
- Forge writes schema-2 root NBT and uses capability/native event adapters. NeoForge writes the established data-component/attachment fields and uses native payload codecs. Unknown extension fields and future stamps are retained or refused safely; migrations make a content-addressed backup before rewriting configuration.
- The Spell Loom now has a server-synchronized preview/details view, 274-symbol searchable picker, 11 backgrounds, five local cosmetic presets, explicit conversion and exact consumption/capacity text. The request context includes menu/session/request UUID, inventory revision and mapping digest.
- `/ans inspect`, `/ans diagnose`, `/ans journal view`, `/ans schools` and `/ans removal_report` are read-only authoritative diagnostics. The transaction HUD renders server receipts for reserve/commit/refund/refusal with per-resource symbols.
- The compatibility panel reports present/absent states as runtime-unverified unless a profile has actually exercised the integration. Patchouli notebook entries and the generated recipe/config references describe carrier consumption, units, caps, restrictions and migration limits. `tools/addon_adapter.py` and `tools/pack_presets.py` provide version-gated fixtures and dry-run/apply pack-author workflows.

## Icon and background deliverable

The icon pack is a finished 3.3.0 deliverable, not a placeholder inventory:

- `tools/icon_art.py` contains the original pixel-grid shape vocabulary for spell, school, element, resource, status, compatibility, ritual, carrier and UI families.
- `tools/generate_icons.py` emits the 274 canonical 16×16 RGBA designs, 1,370 state rasters, 11 composable background frames, legacy aliases, labels, manifest and an independently authored HD32 pack. `tools/verify_icons.py` checks dimensions, alpha margins, hashes, fallback cycles, localization and all resource-pack contents.
- `assets/ars_n_spells/icon_manifest.json` records logical ID, canonical resource, alias/fallback, state variants, source/author/license, permitted transforms, provenance, review status and hashes. No upstream proprietary texture is redistributed.
- `SpellIconRegistry` resolves item-selected → semantic → school → generic → outlined-rune fallback, composes backgrounds with alpha-safe rendering, bounds the cache and clears it on resource reload. The same logical selection is written to Loom output and rendered in the native wheel.
- `docs/3.3.0-icons/` contains the family/background contact sheets and the pack-author instructions. Forge and NeoForge client captures show all five visual states, all backgrounds, GUI scales 1–4, search, resource-pack reload and native-carrier round trips.

The original audit and its failure logs remain under `docs/audit-2026-09-05/` as historical evidence. This ledger and the generated 3.3.0 references describe the corrected implementation and the limits of the evidence above.
