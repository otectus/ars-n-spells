# Ars ’n Spells 3.3.5 — implementation brief

**Purpose:** Give a coding agent a release plan for the reported mana-bar drop, configurable cooldowns for Ars spells in Iron’s spellbooks, failed addon casts, and Ars Affinity compatibility. **Research baseline:** 27 September 2026; repository `main` at [`d805b45`](https://github.com/otectus/ars-n-spells/tree/d805b45fb629d9ae30b97ccc6b3487438c103942), NeoForge branch `port/neoforge-1.21.1` at [`41fac17`](https://github.com/otectus/ars-n-spells/tree/41fac17065c381104b17fdaab307d89ba21b49ab). Both checked-in `gradle.properties` files say **3.3.3**. The supplied `[CastPayment]` log has fields absent from the checked-in Forge `NativePayment.Result`, so first obtain the actual jar/build or commit that emitted it. Do not describe a proposed cause as a confirmed fix.

| Track | Platforms / dependencies | 3.3.5 deliverable |
| --- | --- | --- |
| Forge | Minecraft 1.20.1; Ars Nouveau 4.12.7; Iron’s Spellbooks pinned in the build; Java 17 | Mana regression, inscribed spell cooldown, addon cast/payment fix; test BielGG’s/T.O Magic/Roaring here. |
| NeoForge | Minecraft 1.21.1; Ars Nouveau 5.13.x; Iron’s 3.16.3; Java/toolchain from branch | Port the shared fixes, then integrate **Ars Affinity** as an optional runtime dependency. |

Ars Affinity’s [published files](https://www.curseforge.com/minecraft/mc-mods/ars-affinity/files/all) list 1.21.1 NeoForge, not a verified 1.20.1 Forge build. Its [upstream source](https://github.com/zeroregard/Ars-Affinity) identifies mod ID `ars_affinity`, and its checked-in NeoForge metadata requires Ars Nouveau **and Ars Elemental**. Keep the Forge jar independent of its classes. Do not claim that the Forge 1.20.1 release supports Ars Affinity unless a compatible build is actually identified, obtained, and tested. Feature parity should be backported only if that platform becomes viable. This release may share the 3.3.5 label across both branches, but publish loader-specific artifacts and compatibility notes.

## Severity and execution order

1. **P0: reconcile the report with the exact runtime build.** Record Minecraft, loader, ANS, Ars, Iron’s, BielGG’s, T.O Magic and Roaring versions; mode, costs and source for every cast; compare the user log schema with the checkout. Preserve a copy of the modpack’s config for testing. No sensitive player identifiers in public diagnostic output.
2. **P0: silent mana loss / interrupted spell.** Build small, reproducible tests before changing payment or capacity semantics. A cast may not produce an effect and then fail a payment ANS should have settled before that effect.
3. **P1: inscribed cooldown.** Implement using Iron’s native cooldown pipeline where possible, with server config migration and visible client feedback.
4. **P1: optional Ars Affinity on NeoForge.** Ensure mod-absent launch, same-cast progression, perk effects, and no duplicate rewards.
5. **Gate each loader independently.** Do not release one platform because the other builds.

## A. Ars-primary mana dips while scrolling the hotbar

### Observation and hypotheses

The player reports an Ars mana bar that intermittently drops while scrolling, without intending to cast, in `ars_primary` mode; she has the initial Ars spell book that adds regeneration. There is no measured current/max mana, server log, or exact installed version. Scrolling changes the main-hand item, which **can legitimately change a max-mana attribute or a regen bonus**; it must not silently debit mana when the maximum is unchanged. A lowered *percentage* may also be a changed denominator or stale client HUD rather than a server-side loss.

Relevant Forge paths: [`EquipmentHandler`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/events/EquipmentHandler.java) responds to `LivingEquipmentChangeEvent`, dirties the equipment cache, and reconciles at player-tick END or every 20 ticks; [`EquipmentIntegration`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/equipment/EquipmentIntegration.java) reads main/offhand, armor, Curios and transient Iron’s `MAX_MANA` modifiers; [`ArsManaCalcHandler`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/events/ArsManaCalcHandler.java) defers Iron’s max sync after Ars calculation; [`MixinManaCapability`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/mixin/ars/MixinManaCapability.java) lets native Ars getters and writes run in `ars_primary`; [`NativeManaSync`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/bridge/NativeManaSync.java) sends Ars and Iron’s updates. These are **investigation targets**, not proof that the book causes a debit.

### Reproduce and trace

* Make a dedicated-server test world with ANS 3.3.5 candidate, Ars and Iron’s. Set `ars_primary`; allow both pools to reach full, then set them to distinct known values, e.g. Ars current/max `80/100` and Iron’s `40/200`. Repeat at full Ars mana as a separate case. Add the beginner Ars book; compare an empty main hand, ordinary sword, Ars caster book, Iron’s mana weapon and a Curios spellbook. Scroll slowly and rapidly forward/backward for 60 seconds. Repeat while idle, moving, in combat, holding right-click, and with chat/inventory open; test dedicated server and single-player. Then repeat `iss_primary`, `hybrid`, `separate`, `disabled` and Ars alone. The test should assert the **authoritative server Ars balance**, not HUD pixels alone.
* Capture before/after, by server tick and item ID: Ars native current/max, Iron’s native current/max, active bridge current/max, Ars regen, Iron’s `MAX_MANA` and `MANA_REGEN` modifiers with IDs, selected slot, whether a cast attempt exists, relevant sync packet value, and client display current/max. Correlate hotbar event, equipment reconciliation, native clamp, pool write and packet. Put this under an explicit, rate-limited debug toggle or temporary development instrumentation; never log every frame in production.
* Establish whether (a) max changes from a real held-item modifier, (b) server current falls because a new ceiling clamps it, (c) server current stays constant while only the display changes, (d) a spell or item use actually occurs, or (e) a stale deferred max update executes after a newer equipment change. Check the initial book with and without its regen bonus and after a relog. Do not disable all equipment bonuses merely to hide a displayed symptom.

### Fix contract

* Treat `ars_primary` Ars native balance as authoritative. A no-cast hotbar selection that leaves the true max unchanged must leave current mana unchanged; regen may only raise it. If an actual item bonus is removed, document and apply the chosen clamp to the new true max **once**; swapping back should not trigger another debit at an unchanged max. Align Iron’s mirrored ceiling before any Iron’s-side operation can clamp the Ars pool.
* If stale work is responsible, coalesce deferred max-mana sync per player/tick or attach an equipment generation and re-evaluate the actual final max before applying. If HUD-only, fix packet ordering or the displayed numerator/denominator, retaining server authority. Audit client-only reads and cross-mode shadow values for a misleading visual step.
* Add a GameTest or integration fixture that cycles main-hand items, records both native pools and confirms no phantom debit in `ars_primary`; add a separate case for a legitimate max-bonus removal. A unit test solely checking the handler’s source text does not establish this behavior.

## B. Default cooldown for Ars spells inscribed into Iron’s books

### Current behavior

Forge and NeoForge [`ArsCrossProxySpell`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/spell/irons/ArsCrossProxySpell.java) registers `ars_n_spells:ars_cross_1..N` proxies with `.setCooldownSeconds(0.0)`. Their `getManaCost` returns zero to avoid charging twice; `onCast` delegates to the Ars spell. The cross-mod **category** cooldown in [`CooldownHandler`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/events/CooldownHandler.java) is separate and disabled by default. The existing [`IronsCooldownHandler`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/events/IronsCooldownHandler.java) intentionally skips proxies so it does not double gate a delegated Ars cast. Preserve this distinction.

### Proposed server-config semantics

| Key | Type and proposed value | Meaning |
| --- | --- | --- |
| `inscribed_ars_default_cooldown_ticks` | integer `0..12000`; **40 on a fresh 3.3.5 config**, **0 for existing configs** via schema migration | Per-proxy Iron’s cooldown after a *successful* Ars spell cast from an Iron’s spellbook. `0` retains previous no-native-cooldown behavior. 20 ticks ≈ 1 second at normal server tick rate. |

Place under Cross-Cast Inscription in [`AnsConfig`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/config/AnsConfig.java) on each loader. Use the existing config schema migration pattern: existing worlds do not unexpectedly acquire cooldowns; users who opt in can choose any duration. Validate nonnegative, bounded values and a clear unit. Update the in-game server settings UI, pack-author reference, user guide and tooltip. Record whether editing the server config takes effect immediately or requires restart and implement the documented behavior; do not rely on a registry-time config read before server config initialization.

Apply the cooldown to **the actual proxy spell ID** through Iron’s effective cooldown mechanism, including its reduction modifiers and native client sync. Confirm the upstream 3.16.x API/jar before choosing a hook; if a dynamic per-spell cooldown callback exists, use it, otherwise set the cooldown through the native `MagicData` cooldown service after the delegated cast reports success. Do not globally rewrite all proxies’ `DefaultConfig` at runtime if it is baked or cached. Never impose this setting on a regular Ars book/staff cast, an ordinary Iron’s spell, or an inscribed Iron’s spell in an Ars carrier. A failed cast, invalid carrier, missing Ars payload or rejected payment starts **no cooldown**. Preserve existing category cooldown behavior when explicitly enabled: define combined effect as the intersection of both gates, without adding two identical timers or skipping the new per-proxy cooldown. Avoid imposing a single category-wide timer unless the category option is enabled.

Test two bound books with the same proxy pool ID but different Ars payloads, distinct proxy slots in one book, switching books, Curios-held books, casts from both hands, a failed cast, cooldown reduction attributes, logout/relog and client wheel feedback. Decide and document that a reused proxy ID shares its native cooldown across books; if per-book independence is desired later, it requires a separate persisted key design, not a hidden assumption here. A value of zero should reproduce 3.3.3 behavior.

## C. BielGG’s / T.O Magic / Roaring casts stop after an effect

### What the evidence actually says

The supplied line names spell `bielgg_spells:crystal_barrage/1`, `source=SWORD`, `step=2`, `stage=interrupted_after_effect`, `paid=false`, `reason=INSUFFICIENT_RESOURCE`, `failureUnit=IRONS_MANA`. This shows **an Iron’s-mana leg was unaffordable at that payment point**; it does not by itself show why or prove a Roaring spell failed. The payer and amount are absent from the excerpt. `remaining=[]` in that runtime format must not be interpreted as “zero cost” without examining the matching `CastPayment` code. Crystal Barrage is a concrete regression fixture; separately inventory the actual failing Roaring spell IDs and their cast types. BielGG’s [Forge 1.20.1 files](https://www.curseforge.com/minecraft/mc-mods/bielggs-spells-addon/files/all?version=1.20.1) list `1.5-patchwork` among the releases; Roaring and T.O Magic are listed as optional dependencies on its [dependencies page](https://www.curseforge.com/minecraft/mc-mods/bielggs-spells-addon/relations/dependencies). Do not presume every addon combination uses the same code.

The checked-in Forge [`IronsCastPayments`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/casting/IronsCastPayments.java) quotes at `SpellPreCastEvent`, re-quotes if `SpellOnCastEvent` changes the cost, and commits through [`NativePayment`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/casting/NativePayment.java). [`MixinIronsCastPayment`](https://github.com/otectus/ars-n-spells/blob/d805b45fb629d9ae30b97ccc6b3487438c103942/src/main/java/com/otectus/arsnspells/mixin/irons/MixinIronsCastPayment.java) hooks before the ordinary `onCast` effect. The user’s richer `CastPayment` line likely belongs to a later or different build. **First diff that exact runtime’s cast lifecycle against this baseline**, including any repeated, sword-triggered or delayed payment hooks.

### Reproduction grid and diagnosis

* Forge 1.20.1 server, pinned Iron’s 3.16.x and Ars 4.12.7; ANS exact user build, then the candidate fix. Compare Iron’s + BielGG’s alone, plus ANS, plus T.O Magic, plus Roaring, then all four. Record mod jar hashes and optional addon versions. For each named failing spell, cast from sword, native spellbook, scroll if supported, and the addon’s intended carrier; compare levels 1 and higher, just-enough, exact-cost, one-below, high mana, and zero mana. Test `ars_primary`, `iss_primary`, `hybrid`, `separate` and `disabled`. For continuous/multistage/recast spells, stop early, finish, change weapons and interrupt by damage, cancel, death or logout. Do not infer source-independent behavior from a sword-only result.
* Record per attempt ID and step: native spell cost, adjusted cost after all upstream events, any repeated-cast/cost flags, carrier, source, mode, routing snapshot, charged quote and unit legs, available native balances, selected active bridge balance, reservation/debit/refund, cooldown and the first effect tick. Redact player UUIDs from shared examples. Check whether an addon independently removes mana before the second payment, whether ANS quotes one stage but settles another, whether a conversion/split creates an Iron’s leg in `ars_primary`, and whether `SpellOnCastEvent` changes a cost after the affordability gate.
* If the same failure occurs without ANS, record an upstream/addon issue and avoid ANS-specific hacks. If the cast works without ANS, find the **first** divergent transaction; do not target a namespace-wide exemption. Compare direct Iron’s sword casting to Ars-in-Iron’s proxy casting; Crystal Barrage’s `source=SWORD` is not evidence that the proxy path caused the failure.

### Correctness requirements

* A cast step must be priced and checked **before** its irreversible effect. For staged casts, specify whether the spell charges once at start or per effect/interval according to the upstream and addon contract. If genuinely per-step, reserve or preflight the step amount before it occurs; a failed later step can stop future effects but cannot honestly roll back earlier world changes. If a single initiation cost, do not bill the same cast twice because an addon sends another event or animation tick.
* Use one attempt identity and immutable per-attempt routing/cost inputs across pre-cast, cost modification, execution and interruption. Reconcile final adjusted cost at the authoritative payment boundary; never treat `SpellPreCastEvent` alone as final if addons can modify `SpellOnCastEvent`. Check double-debit, partial dual-pool debit/refund, alternate LP/aura payment, recast and creative exemptions. Preserve compatibility with a third party overwriting a non-critical upstream method; validate injection location against the pinned jar and give a safe failure if the hook no longer applies.
* Display a brief actionable error (required/current resource, only if available to that player) instead of the generic “check your resources” for a genuine shortage. With debug on, give one concise trace per failing attempt with spell ID, source, stage, quote and units. No log storm, speculative free cast, hardcoded exemption for `bielgg_spells`, or suppression of legitimate addon costs.

**Acceptance:** Crystal Barrage and the enumerated Roaring-related spells finish normally with sufficient resources in their supported configurations; no mid-effect ANS payment failure; insufficient resources prevent the next effect and debit nothing beyond already successful paid stages; no double charge or phantom cooldown. Add loaded GameTests for a native Iron’s sword with a custom spell cost modifier and a delayed/recast spell; use a real addon pack smoke test for behavior unit fixtures cannot establish.

## D. Ars Affinity compatibility on 1.21.1 NeoForge

Ars Affinity tracks progress per **Ars `SpellSchool` and glyph mana cost** in its [`SpellTrackingMixin`](https://github.com/zeroregard/Ars-Affinity/blob/main/src/main/java/com/github/ars_affinity/mixin/SpellTrackingMixin.java) on `SpellResolver.onResolveEffect`. Its [perk helper](https://github.com/zeroregard/Ars-Affinity/blob/main/src/main/java/com/github/ars_affinity/perk/AffinityPerkHelper.java) reads its own player data; [Mana Tap](https://github.com/zeroregard/Ars-Affinity/blob/main/src/main/java/com/github/ars_affinity/event/PassiveManaTapEvents.java) restores mana through Ars `IManaCap.setMana`; [healing amplification](https://github.com/zeroregard/Ars-Affinity/blob/main/src/main/java/com/github/ars_affinity/event/SpellAmplificationEvents.java) reads Ars events. ANS has **its own** [`AffinityData`](https://github.com/otectus/ars-n-spells/blob/41fac17065c381104b17fdaab307d89ba21b49ab/src/main/java/com/otectus/arsnspells/data/AffinityData.java) and Iron’s affinity handler. These similarly named systems have different data, schools and semantics; **do not merge save formats or silently replace a perk tree**.

### Desired interoperability

1. **No extra progress for a single Ars cast.** Test Ars book/staff casts and an Ars payload delegated from the Iron’s native wheel. The latter calls the real Ars resolver via ANS proxy, so Ars Affinity may already count it. Trace exact invocation before adding any event bridge; if it already counts once, leave progress to its own mixin. For projectile or repeated resolution, follow Affinity’s native behavior and verify against a standard Ars spell of the same shape. Iron’s native spells should not gain *glyph* progression unless a clear, opted-in mapping exists: Iron school IDs are not automatically Ars glyph schools.
2. **Apply native perks once.** An Ars Affinity bonus attached to an Ars event should still affect the delegated Ars resolver, while ANS’s optional school progression and resonance keep their documented behavior. Test numerical stacking for spell power, healing, defensive effects and Mana Tap. In `ars_primary`, Mana Tap must increase the Ars authoritative pool by the correct amount without recursion; in other modes confirm the existing bridge routing and cap. Do not manually add that reward again if Affinity already called `IManaCap.setMana`.
3. **Keep saves and UI owned by their mods.** Affinity progress, allocations, abilities and commands remain in Ars Affinity’s capability; ANS data remains in its own capability. On reconnect, death/respawn and dimension change, both persist and sync correctly. Both UIs and mana overlays remain available without overlap or misleading duplicate tooltips.
4. **Optional linkage only.** Gate any compat registration on the mod ID and compatible version; isolate direct Affinity class references so a server without it starts. Respect its Ars Elemental dependency and the NeoForge branch’s own optional Ars Elemental setup. Prefer normal Ars hooks already emitted by delegated casts. If an API adapter is actually needed, compile it conditionally and ensure a mod-absent runtime profile verifies class loading. Do not create a Forge-only shim pretending to provide Affinity.

### Integration matrix

| Combination | Required result |
| --- | --- |
| ANS NeoForge + Ars only | Launch; mana/casting unchanged; no Affinity classes loaded. |
| ANS + Iron’s, without Affinity | Native and proxy spells work; no new dependency. |
| ANS + Ars Affinity + its required Ars Elemental, without Iron’s | Ars-native casts progress/activate perks; ANS remains usable. |
| All four mods | Native Ars and proxy Ars each progress exactly once; native Iron’s has no invented glyph progress; Mana Tap and other perks work in all five mana modes. |

Use the actual published `ars_affinity` **1.1.1** jar in the final smoke profile; the public source inspected above appears to contain **1.1.0** metadata. Confirm its binary behavior before treating source internals as an exact contract. Test server and client with the same jars. If public API is absent, favor zero integration code when observed behavior already works, and document verified compatibility; only add a narrow adapter for a reproduced gap.
