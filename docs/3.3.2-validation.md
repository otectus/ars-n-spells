# 3.3.2 release verification

Date: 2026-09-07.

## Implementation and parity

Iron's Spells has the same contextual mana-bar bug on both supported loaders:
`SyncManaPacket` and `ClientMagicData.getPlayerMana()` expose whole-number mana,
while `ManaBarOverlay.shouldShowManaBar(Player)` compares it with the raw double
maximum. A full fractional pool can therefore display `1001/1001` while still
passing the native "mana below maximum" check.

Both builds now correct the shared visibility predicate at RETURN, using the
HUD's integer precision. Existing hidden results remain hidden; Always/Never,
spectator handling, and Iron's held-casting-item rule remain intact. Fixing the
shared predicate also restores XP when the mana bar hides at the XP anchor.
The mixin is client-only, optional, and gated on Iron's presence.

The named NeoForge checkout now includes the pending audit implementation and
3.3.1 changes, including transaction receipt HUD removal, that previously lived
in the audit worktree. The original clean checkout was archived before migration
at `C:/Projects/ars-n-spells/build/neoforge-before-3.3.2.zip`. Git history and run
worlds were preserved. The release version is 3.3.2 in both repositories.

Parity checks passed:

- All 32 shared domain contract and golden-fixture sources match the canonical-LF
  SHA-256 manifest in both repositories.
- `ManaBarVisibility.java` and all six `ManaBarVisibilityTest` cases are identical.
- The visibility mixins differ only in the Minecraft attribute-holder API and
  the comment naming the loader's GUI event.
- The icon manifest and all 1,416 shared textures match. Both icon verifiers pass
  for 274 logical icons, 11 backgrounds, and their native/HD states.
